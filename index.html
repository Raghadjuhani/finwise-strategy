Slide 5 · The Bet

The Bet (Growth Hypothesis)

Growth hypothesis

If we change sign-up and onboarding to be personalized based on user type and deliver a fast, clear result using the user's own real data, then Trial→Paid conversion will increase, because the Aha moment, a specific, real insight the user can immediately see is! theirs is what proves value, and proven value is what earns a purchase decision.

The bet

We're betting on: personalization and speed-to-result, not acquisition volume or price. Specifically — a short quiz at sign-up that identifies user type (e.g., biggest financial question: cash flow, budgeting, or fundraising prep) so the first model shown is the right model for that business, combined with a lean onboarding path that gets from sign-up to that personalized first result as fast as possible, on the user's own real data.

Slide 7 · The Mechanic

The Mechanic (Gamification)

Mechanic + rationale

Retention has to be earned before conversion is asked for — a user who's built a habit resolving open items in their own data (a banner or email flagging transactions to categorize before their forecast updates) has already proven the product's value to themselves. That's what makes the paywall, placed at their first personalized model, land as a natural next step rather than an interruption.

This targets our weak point: 40% one-year retention. The loop is concrete: Trigger ("3 transactions need categorizing before your forecast updates") → Action (categorize them) → Reward (forecast shifts, caused by that action) → Investment (invite the accountant, who now gets every future trigger too). Each cycle makes the product harder to leave and more relevant to return to, instead of relying on acquisition to replace churned users.

Action and Investment aren't new mechanics — Action is the same behavior as trial Activation (Import Data % / Modeling %), and Investment is the same as Expand in our growth loop. This tightens the plan we already have, and fixes the earlier sequencing error, where Trigger referenced a past event instead of an open one.

Slide 8 · The Signals

The Signals (Metrics)

Leading indicators

Average Sessions Per User, the metric most correlated with Trial→Paid conversion (+0.58) across the 13 month data, indicating that how often a trial user returns predicts conversion more than how long they stay per session or how much of any single feature they use.

Lagging indicators

Trial to Paid conversion rate, currently 2%, and 1 year retention rate, currently 40%. Both are business outcomes we can't move directly, we earn them by moving Average Sessions Per User consistently over time.

+0.58

Correlation

Data pattern

Sessions Per User shows a Ceiling pattern, climbing through 2024 then flattening at 9 by Sept–Oct, the same months with two of the highest conversion rates (2.08%, 2.04%). That co-movement (+0.58 correlation) is why it's the leading indicator, but the ceiling means conversion gains may need other levers once engagement caps out.

Slide 9 · The Validation

The Validation (Experiment)

A/B test · 50/50

A/B test (50/50 split), run at the trial-cohort level. This is a single, discrete change to onboarding and the habit loop — not multiple competing variants needing dynamic traffic allocation — so a clean control group is enough to isolate the effect. It also gives an unambiguous causal read before we commit the personalized onboarding + habit loop to all trial users.

Hypothesis + primary metric

2% → 8%

If we replace generic sign-up/onboarding with a personalized flow (user-type quiz + fast result on real data) and add the Trigger→Action→Reward→Investment habit loop (open-item banner/email → categorize → forecast update → invite collaborator), then Trial→Paid conversion rate will increase from the current 2% baseline toward 8%.

Guardrail + read date

−3 pts

One-year retention must not drop more than 3 points from the 40% baseline — a conversion win that trades off retention isn't a real win. Read date: Set before launch. Primary metric at 4 weeks (trial length + one habit-loop cycle); retention guardrail at 90 days, since it can't be honestly read sooner.

Slide 10 · The Model

The Model (Pricing)

Value Creation Reverse-trial → Subscription

Growth stage + monetization model

Value Creation: 2% conversion, 40% retention value isn't proven at scale yet, so pricing has to fix that first, not capture revenue from it. Model: Reverse-trial → Subscription. Full access up front, converting to recurring paid. Fits value that compounds with data and repeated use. Freemium's premature, it would mask the value problem, not solve it.

Recommendation + bet

Move the paywall from a fixed day-14 calendar cutoff to a value-triggered boundary: it appears the moment a trial user completes their first personalized financial model on real imported data — the point where they’ve actually experienced the product’s core value, reached faster through personalized onboarding (user-type quiz + fast result on real data) and reinforced by the habit loop (Trigger → Action → Reward → Investment) that keeps them returning before that moment arrives.

This is a packaging bet, not a price change — we’re not asking users to pay more, we’re asking them to decide at the right moment instead of an arbitrary one.

Supporting signal

If this is working, conversions should cluster tightly around the activation event (first completed personalized model) rather than scattering across, or getting lost before, day 14. Concretely:

• Trial→Paid conversion rate moves from 2% toward the 10% target, read at 4 weeks.

• Time-to-conversion should compress and concentrate near the activation moment, not spread evenly across the trial window.

• One-year retention holds within 3 points of the 40% baseline (guardrail) — confirming the lift comes from better-timed, better-proven value, not from converting users who churn faster
